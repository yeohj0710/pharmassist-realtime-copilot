# 무인 수집 운영 지시서

한 달 내내 사람 없이 도는 수집 에이전트를 위한 문서다. 출처와 활성화 절차는
`DATA_SOURCE_ACTIVATION.md`에 있고 여기서 되풀이하지 않는다. 이 문서는 **오래
도는 동안 무엇을 해도 되고 무엇을 하면 부채가 되는지**만 정한다.

## 0. 한 줄 원칙

**인용해 오는 일은 얼마든지 돌려도 된다. 판단이 들어간 문장을 만드는 일은
돌리지 않는다.**

약사 검토 큐가 179건인데 검토 완료가 0건이다. 승인이 필요한 산출물을 더
만들면 자산이 아니라 부채가 늘어난다. 아무도 읽지 않은 문장이 상담에 그대로
나가기 때문이다.

## 1. 시작 전에 사람이 해야 하는 일

**이게 없으면 에이전트는 한 달을 돌려도 아무것도 못 한다.** 공식 어댑터 4종은
코드가 다 있지만 한 번도 실행된 적이 없다.

- `data/mfds-otc-candidate/` 없음
- 서비스키 4개 모두 미설정
- 어댑터마다 "No credentialed response was fetched" 표시

공공데이터포털에서 활용신청 후 `.env`에 키 4개를 넣는다. 키 이름과 operation
path는 `DATA_SOURCE_ACTIVATION.md`에 있다. 활성화 당일 Swagger 대조도 그
문서를 따른다.

## 2. 출처 신호등

### 초록 — 무인으로 계속 돌려도 되는 곳

공공데이터포털(data.go.kr) 4종. 전부 공식이고 이용약관이 명시돼 있다.

| 데이터셋               | 무엇을 메우나                                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| e약은요 15075057       | 비어 있는 `indication_summary` — 타세놀·게보린브이·액티피드·하티손이 지금 빈칸이다                                             |
| 제품 허가정보 15095677 | 팩에 아예 없는 제품군. 여드름 각질용해제(벤조일퍼옥사이드·살리실산·아젤라산), 암브록솔, 로페라미드, 스코폴라민 패치가 전무하다 |
| DUR 품목정보 15059486  | 병용·연령·임부 금기                                                                                                            |
| DUR 성분정보 15056780  | 성분 단위 금기                                                                                                                 |

### 노랑 — 이미 받아온 것만 다시 쓴다

이미 수집된 registry 776건. **다시 크롤링하지 않는다.** 팩에 반영된 건 207건뿐이라
여기서 나올 게 아직 많다.

### 빨강 — 계약이 확인되기 전에는 켜지 않는 곳

**약학정보원(health.kr).** 저장소가 일부러 스크래퍼를 만들지 않았고,
`assertHealthKrContract`가 코드로 막고 있다. 서면 계약이 상업적 이용, 캐시,
파생 데이터, 재배포, AI 컨텍스트 사용 **다섯 가지를 모두** 승인해야 어댑터를
켤 수 있다.

읽는 속도를 사람 수준으로 낮추는 것과 권한이 있는 것은 다른 문제다. 느리게
읽어도 모아서 제품 DB에 넣고 상담에 쓰는 이상 위 다섯 항목에 걸린다. 계약이
확인되면 3절의 브라우저 경로로 켠다. **에이전트가 게이트를 우회하거나
`agreementId`를 지어내지 않는다.**

블로그·약사 커뮤니티·제품 상세페이지·해외 라벨은 계약과 무관하게 임상 근거로
쓰지 않는다. 출처가 공식이 아니면 수집 대상이 아니다.

## 3. 속도 손잡이

한 회차에 몇 건, 몇 시간마다 돌지는 전부 여기서 정한다. 코드를 고치지 않고
값만 바꾼다. 에이전트는 이 값을 **읽기만 하고 스스로 올리지 않는다.**

```text
COLLECT_BATCH_SIZE=20        # 한 회차에 처리할 item 수
COLLECT_INTERVAL_HOURS=1     # 회차 간격 (시간)
COLLECT_DAILY_CAP=200        # 하루 상한. 도달하면 그날은 멈춘다
COLLECT_ITEM_DELAY_MS=9000   # item 사이 최소 간격
COLLECT_JITTER_PCT=35        # 간격에 주는 무작위 편차 (%)
COLLECT_SOURCE=mfds          # mfds | browser
```

`COLLECT_ITEM_DELAY_MS`와 `COLLECT_JITTER_PCT`는 브라우저로 열어 읽을 때
쓴다. 9초에 편차 35%면 6~12초 간격으로, 사람이 페이지를 훑는 속도다. 공식
API(`COLLECT_SOURCE=mfds`)는 provider 정의의 `requestsPerSecond`를 따르므로
이 두 값을 무시한다.

기본값으로 얼마나 걸리는지 미리 보고 정한다.

| 대상                            | 건수 | 기본값(하루 200건) |
| ------------------------------- | ---- | ------------------ |
| registry 미반영분               | 569  | 약 3일             |
| 미등록 성분                     | 210  | 약 1일             |
| 크로스워크 후보(감사 실패+중복) | 59   | 반나절             |

값을 올리기 전에 **중단 조건(8절)이 먼저 걸리는지** 확인한다. 하루 상한을
올려서 큐 250건을 넘기면 수집이 아니라 부채가 쌓인 것이다.

### 브라우저로 읽는 출처를 켤 때

`COLLECT_SOURCE=browser`는 계약이 확인된 출처에만 쓴다. 약학정보원은
`assertHealthKrContract`가 `agreementId`와 다섯 가지 권한(상업적 이용, 캐시,
파생 데이터, 재배포, AI 컨텍스트)을 전부 요구하므로, 그 값을 넣기 전에는
어댑터가 켜지지 않는다. **에이전트가 이 게이트를 우회하거나 값을 지어내지
않는다.** 계약 근거는 사람이 넣고, 그 내용을 `SourceSnapshot`의 terms에
묶는다.

속도를 사람 수준으로 낮추는 것은 서버 부담을 줄일 뿐, 모아서 제품 DB에
넣고 상담에 쓰는 것이 허용되는지와는 별개 문제다. 둘을 같은 것으로 다루지
않는다.

## 4. 작업 큐 설계

한 달을 버티려면 큐가 **중복 제거되고 재개 가능**해야 한다. 같은 계열 루프에서
일감의 71%가 중복으로 버려진 적이 있다.

- 작업 단위는 `item_seq` 하나. 이게 dedup 키다.
- 완료·실패·건너뜀을 각각 기록한다. 실패만 재시도하고 완료는 다시 집지 않는다.
- 한 번에 처리할 양을 고정하고, 남은 목록은 파일로 남긴다. 프로세스가 죽어도
  다음 회차가 이어받는다.
- **에이전트가 상태 파일을 직접 고쳐 쓰지 않는다.** 스크립트가 쓰고 에이전트는
  읽기만 한다.

## 5. 해도 되는 일

1. **허가정보 전량 수집과 정규화.** 품목기준코드·성분·함량·제형·효능효과를
   원문 그대로 가져와 candidate로 저장한다.
2. **미등록 성분 210개 채우기.** 제품이 참조하는 성분 id 210개가
   `pack.ingredients`에 없다. 공식 성분명으로 등록만 하면 된다. 검사가 조용히
   통과하던 버그의 원인이었다.
3. **크로스워크 후보 제안.** 감사 실패 21건과 같은 `item_seq` 38쌍에 대해
   근거를 붙여 **제안만** 한다. 확정은 사람이 한다.
4. **차이 표 만들기.** 같은 증상 경로 안 제품들의 성분·함량·제형·적응증을
   허가원문에서 뽑아 표로 정리한다. 문장이 아니라 표다. 표가 있으면 문구는
   나중에 사람이 빨리 쓴다.

## 6. 하지 말 것

- 카드 문구(`choose_when`, `comparison_note`, `differentiators`) 생성.
  기계가 쓴 문구가 아세트아미노펜을 관절통에 "소염진통 작용이 필요한 경우"라고
  적은 적이 있다. 항염 작용이 없는 성분이다. 양이 늘면 이런 게 묻힌다.
- `verified`, `published`, `pharmacist_reviewed`를 올리는 것.
- `clinicalUseProhibited` 해제.
- 공식 레지스트리에 없는 제품을 만들어 채우는 것.
- 테스트나 빌드 가드를 느슨하게 고쳐 실패를 지우는 것. 가드가 울리면 데이터를
  고치지 가드를 고치지 않는다.
- 생성된 팩 JSON을 손으로 고치는 것. 생성 파이프라인을 고친다.

## 7. 매일 남길 것

하루치가 검증 가능해야 한 달이 검증 가능하다.

- 그날 처리한 `item_seq` 수, 성공·실패·건너뜀
- 새로 채워진 필드 수(적응증, 성분 등록, DUR)
- 실패 사유 상위 목록
- **사람이 표본을 직접 열어 볼 목록 10건.** 게이트가 초록이라고 품질이
  보장되지 않는다. 이전 코퍼스 작업에서 통과한 산출물에 결함이 있었다.

## 8. 중단 조건

다음 중 하나면 그날 작업을 멈추고 사람을 기다린다.

- 같은 실패가 연속 3회차 반복
- 스키마 불일치나 해시 불일치
- 응답 필드가 문서와 다름(Swagger drift)
- 팩 기준선(claims 483 / protocols 44 / options 337)이 예고 없이 변동
- 검토 큐가 250건을 넘음 — 이건 수집이 아니라 부채가 쌓이고 있다는 신호다

## 9. 배포까지가 한 세트

수집만 돌고 배포가 빠져 사이트가 옛 데이터에 멈춰 있던 적이 있다. 수집 →
`data:build:pack` → 게이트 → 커밋 → 배포까지 한 회차로 묶는다. 게이트가 하나라도
빨간불이면 배포하지 않고 그 회차를 실패로 남긴다.
